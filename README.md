# 健康守护者

今天的训练刚结束，手比昨天更酸。你记得治疗师说过不舒服就停，却想不起上次的疼痛是多少。这次变化该怎样带回复诊，也不太确定。

健康守护者先让人慢下来。开始前看一遍风险，训练后如实记下感受，再把选择、异常和问题放进同一份交接单。下次见到医生或康复治疗师时，不必只说“好像还行”。

[在线使用（GitHub Pages）](https://joyceleo326.github.io/JianKangShouHuZhe/) · [仓库主页](https://github.com/JoyceLeo326/JianKangShouHuZhe)

> **医疗边界**：本项目不诊断疾病，不自动开具、批准或调整处方，也不替代医生、康复治疗师或当地急救服务。处方始终是待专业人员复核的草稿；出现胸痛、呼吸困难、意识异常、突然单侧无力、口角歪斜或语言异常等警示症状时，应停止使用并立即联系当地急救服务。

## 从“今天能不能练”开始

1. **进入本机工作区**：在线静态版本可直接开始，不要求登录。患者、评估、草稿和记录默认保存在当前设备。
2. **建立基础档案**：录入患者、设备和既有方案信息；设备登记只表示档案存在，不代表应用已经连接、读取或验证硬件。
3. **完成训练前自查**：记录疼痛、麻木、肿胀、皮肤状态和其他异常。红旗症状会优先给出停止与求助提示，而不是继续推荐训练。
4. **核对处方状态**：只有已由专业人员确认的方案才能作为训练边界；在应用中新建的处方保持“草稿”状态。
5. **比较至少三个安全候选**：今日复盘结合上次完成情况、疲劳、不适、当前疼痛、可用时间和处方状态，展示不同下一步的收益、权衡、安全边界和适用依据。
6. **人工选择与确认**：用户明确接受取舍并确认后，才形成当前版本；应用不会替用户执行训练。
7. **记录真实结果**：保存完成、舒适、疲劳、不适或中止等反馈。下次打开复盘时，会先看到这次结果；“继续、复盘、暂停、专业确认”的顺序也会随之改变。
8. **形成专业交接**：下载包含目标、自查、处方状态、候选比较、人工选择、反馈和下一步问题的交接单，供后续复核。

### 第一次体验建议

打开在线入口后，先使用示例数据完成一次“今日康复复盘”：

1. 在训练前自查中分别尝试无异常和出现不适两种情况，确认推荐顺序确实改变；
2. 阅读三个候选的收益与代价，再确认一条路径；
3. 下载交接单，确认它记录的是选择依据而不是自动医疗结论；
4. 回填一次疲劳或不适反馈，重新进入复盘，观察下一轮是否把复核或暂停提前；
5. 最后导出个人数据，了解当前浏览器实际保存了哪些内容。

## 它帮你留下什么

康复中的细小变化很容易在几天后变得模糊。下面这些记录会留在同一个工作区，方便自己回看，也方便交给专业人员复核：

- 患者、评估、处方草稿、训练记录、设备与报告档案；
- 训练前症状自查，以及卒中和其他警示症状分流；
- 上次反馈、当前疼痛、疲劳、不适、处方状态和可用时间都会影响下一步的顺序；
- 至少三个可比较候选，以及收益、权衡、安全边界和人工确认；
- 已确认的 V1、训练后的真实感受，以及下一轮为什么改变；
- 24 幕手部康复叙事，覆盖准备、安全、选择、确认、执行、反馈、回流与交接；
- 可真实下载的康复交接单，以及报告草稿、PDF / CSV 和个人数据导出；
- 报告来源、字段缺失和人工复核状态检查；
- 敏感信息授权版本、角色操作审计、个人数据导出与删除；
- 离线写入队列、同步冲突识别和人工保留本地/远端版本；
- 可选 OpenAI-compatible 信息整理助手，使用结构约束、引用白名单、拒答边界和人工采纳记录；
- Expo / React Native / React Native Web 跨端界面，以及 320px 起的移动端布局。

## 信息助手如何工作

信息助手只整理这一轮明确提供、带引用编号的已有记录。它不能诊断、开处方、调整剂量，也不能补出没有提供的健康事实。证据不足、风险不明或出现警示症状时，它必须停下来，提醒用户寻求专业复核。

模型能力是可选的 BYOK（用户自带 Key）扩展：

- 未配置模型时，其余患者、训练、报告和交接流程仍可使用；
- API Key 不写入持久化存储，刷新或重新打开应用后需要重新输入；
- 请求会发送到用户选择的模型服务或代理地址，因此使用前应阅读该服务的数据政策；
- 不要把 Key 写入 `.env.example`、源码、截图、Issue、PR、测试数据或导出档案。

## 本地运行

需要当前 Node.js LTS 与 npm：

```bash
git clone https://github.com/JoyceLeo326/JianKangShouHuZhe.git
cd JianKangShouHuZhe
npm ci
npm run web
```

Expo 会在终端显示本地 Web 地址。原生开发也可以使用：

```bash
npm run android
npm run ios
```

`npm run ios` 需要支持 iOS 开发的 macOS 环境；Android 需要可用模拟器或设备。

### 可选账号 API

核心公开体验不需要后端。若要在受控环境中测试账号与同步参考实现：

1. 将 `.env.example` 复制为本机 `.env`，不要提交该文件；
2. 为 `JWT_SECRET` 设置足够强且独立的随机值；
3. 将 `CORS_ORIGIN` 限定为实际前端来源；
4. 运行 `npm run server`，默认监听 `3001`；
5. 前端通过 `EXPO_PUBLIC_API_BASE_URL` 指向该 API 后重新构建。

服务端使用本地 JSON 文件保存测试数据，适合作为功能参考，不应未经数据保护、持久化、备份、访问控制和合规评估就处理真实健康信息。

```bash
npm test
npm run check:syntax
npm run build:pages
npm run check:recovery-web
```

- `npm test` 覆盖反馈闭环、因果排序、AI 输出治理、隐私授权与审计、报告导出、离线队列、冲突合并、账号权限和空数据初始化；

- `build:pages` 生成 GitHub Pages 静态产物；
- `check:recovery-web` 使用本机 Chrome 或 Edge 验证主要康复旅程、真实下载、44px 触控区和横向溢出。

## 构建与部署

```bash
npm run build:pages
```

发布目录为 `release/github-pages-deploy/`：

- `.github/workflows/ci.yml` 安装依赖并运行自动化验证；
- `.github/workflows/github-pages.yml` 构建并上传静态 Pages 产物；
- `vercel.json` 可把同一 Pages 静态产物作为根路径部署；

- 静态 Pages 版本不部署 `server/`，也不会把 `.env` 或 `JWT_SECRET` 打进前端。

## 数据、隐私与安全

- 静态版本使用 AsyncStorage / 浏览器本地存储保存工作区。清理站点数据、受限隐私模式或更换浏览器配置文件可能删除记录，请使用个人数据导出与交接单留档。
- 未配置 `EXPO_PUBLIC_API_BASE_URL` 时没有云端账号与同步；配置后，登录数据和应用快照会发送到部署者指定的 API。
- 本地和远端在同一内容上同时变化时，应用会建立冲突记录并等待人工选择，不会静默覆盖。
- 健康数据具有高度敏感性。公开演示只应使用虚构或充分匿名化数据，不应录入真实姓名、联系方式、病历号或未经授权的医疗记录。
- 处方、报告和 AI 输出都保留“草稿 / 待复核”边界；人工确认记录不等于医疗专业人员批准。

## 已知边界

- 这是康复记录与交接工具，不是医疗器械、诊断系统、急救分诊系统或远程医疗服务。
- 设备中心当前记录设备档案和同步状态，不证明已经接入、校准或验证任何真实传感器。
- PDF / CSV、趋势和汇总分依赖人工录入数据；不完整或错误数据会直接影响输出。
- 静态站没有跨设备同步；可选 JSON 文件服务端也不是面向真实医疗场景的生产数据库。
- 外部模型可能受网络、配额、内容政策和数据处理条款影响；敏感记录不应在缺少授权与风险评估时发送。
