# 健康守护者多端正式交付计划

日期：2026-08-30  
状态：已批准。用户已明确要求尽快全量实现，并补充 Android 安装后应呈现真实 App 体验；用户随后取消演示视频。

## 目标

以 `codex/productize-health-20260813` 的成熟跨端产品为基线，保留已有手部康复记录、安全自查、人工复核、反馈回流、报告与隐私治理能力，完成同一产品的正式 Web、Windows 和 Android 交付。

## 不可缩减的完成定义

1. 正式应用界面不出现 `Demo`、`演示`、`样例版`、`原型`、`预览版` 等降低真实产品感的措辞；测试脚本内部名称可保留，但不得进入用户界面或正式下载页。
2. Android 用户可下载签名 APK、安装、从桌面图标启动并离线使用核心流程；应用名称、图标、启动页、版本号、包名和本地持久化均完整。
3. Web 用户可从正式产品页进入完整在线应用，完成建档、安全自查、方案复核、训练反馈、报告/交接单和个人数据导出；刷新后本地数据仍在。
4. Windows 用户可下载发布包、启动 `HealthGuardian.exe`，在独立窗口中使用同一核心交互并保存本地数据。
5. Netlify 发布正式产品页和 Web 应用；同时保留独立静态镜像。不得把任何第三方网络在中国大陆的可达性描述为绝对保证，必须提供 APK 直装与备用下载入口。
6. 医疗边界必须保留：应用不诊断、不自动开具或批准处方、不替代专业人员或急救服务；设备档案不得伪装成已接入真实硬件。
7. 交付物包含正式 URL、APK、Windows 包、SHA256、版本信息、安装说明、已验证范围与已知网络边界。

## 实施任务与 TDD/QA 顺序

### HG-01 正式产品身份与跨端文案

- RED：增加正式产品文案扫描测试，先证明当前用户界面仍含不允许词语或旧发布命名。

- REFACTOR：统一脚本、构建目录和版本命名，不改变领域行为。
- QA：Android 竖屏、移动 Web 与桌面 Web 均不暴露内部测试/演示身份。

### HG-02 Web 产品页、在线应用与可安装体验

- RED：增加发布站结构测试，要求 `/` 为正式产品与下载入口、`/app/` 为完整应用、manifest 与离线壳存在。

- QA：至少在 390x844 与 1440x900 验证主要闭环、下载链接、刷新持久化和无横向溢出。

### HG-03 Android 正式 APK
